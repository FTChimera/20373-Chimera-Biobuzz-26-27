08 / Position

Keep localization, vision, and geometry explicit.

The default follower localization path is configured through the active robot profile and Pedro Pinpoint localizer. Limelight is a profile-managed camera wrapper that can provide AprilTag, color, or neural-detector data. The new field utility is separate JTS-backed geometry for contact checks. These layers should cooperate without silently overwriting each other.

Call follower and Limelight from an OpMode

Use the profile-created follower for localization. If the active profile includes the optional Limelight wrapper, start a selected pipeline and update the wrapper while reporting Pedro poses.

Follower follower = Constants.createFollower(hardwareMap);
Limelight limelight = Constants.hasMechanism(Limelight.class)
    ? Constants.createLimelight(hardwareMap) : null;
follower.setStartingPose(Constants.RED_DEFAULT_START_POSE);

waitForStart();
if (limelight != null) limelight.start(Limelight.Pipeline.APRIL_TAG);
while (opModeIsActive()) {
    follower.update();
    if (limelight != null) {
        limelight.updateRobotOrientation(follower.getPose().getHeading());
        limelight.LLUpdate();
    }
    telemetry.addData("Pedro pose", follower.getPose());
    telemetry.update();
}
if (limelight != null) limelight.stop();

Pinpoint belongs in the robot profile

RobotConfigurations supplies Pinpoint hardware name, pod offsets, encoder directions, distance unit, and pod resolution through PinpointConstants. RobotConstants.createFollower(...) puts those constants into its FollowerBuilder(...).pinpointLocalizer(...) flow. Changing one of these in an autonomous op mode creates profile drift.

.pinpointConstants(new PinpointConstants()
    .hardwareMapName("pinpoint")
    .forwardPodY(/* measured value */)
    .strafePodX(/* measured value */)
    .forwardEncoderDirection(...)
    .strafeEncoderDirection(...))

Profile construction does not certify calibration. Measure physical offsets and validate follower behavior before treating follower tuning as competition-ready.

Use the Limelight wrapper and select a pipeline deliberately

library/hardware/webcam/Limelight.java extends Mechanism and exposes APRIL_TAG, COLOR, and NEURAL_DETECTOR pipelines. Normal creation flows through Constants.createLimelight(...) or the aggregate mechanism set if the active profile registers it.

PipelineCurrent intended use
APRIL_TAGShared teleop can start the optional wrapper in this mode for cached fiducial/pose information.

Pose data needs an explicit coordinate boundary

Constants.FTC_COORDINATE_SYSTEM is the repo's inverted FTC coordinate system. The Limelight wrapper converts a Pedro heading before it reaches FTC/Limelight orientation calls and converts MT2 pose data back through MathUtils.units.toPedroPathing(...). Keep those conversions in the wrapper/math layer; do not scatter one-off degree/radian or axis swaps across op modes.

Practical ruleUse Pedro Pose inside TeamCode pathing/planner logic. When crossing an FTC SDK or Limelight boundary, use the existing coordinate and unit helpers and document the expected frame.

Field is a geometry utility, not an autonomous strategy engine

library/game/Field.java uses JTS geometry to create ordered polygons and circles, project a robot footprint through a velocity sweep, and classify contact as OUTSIDE, PARTIAL, or OVERLAPPING. It exposes placeholder shapes and alliance-specific autonomous midline boundaries while the game geometry remains preseason work.

Field.ContactState state = Field.Boundaries.AUTO_MID_LINE_BLUE
    .getContactState(position, velocity, deltaTime);

The contact check considers both the robot footprint and sweep rather than only the robot center. That makes it suitable for constraints like “would a moving robot cross this boundary?” but it does not generate a detour or replace a path planner.

Validate in the correct order

Pose and vision validation
  1. Verify follower construction and Pinpoint orientation through the profile before tuning paths.
  2. Use safe static and low-speed movement checks before trusting a pose.
  3. Confirm the active Limelight pipeline and call LLUpdate() regularly when consuming cached wrapper results.
  4. Treat Limelight mounting dimensions and distance-derived detector positions as calibration targets until measured.
  5. Run FieldTest for pure geometry changes, then test field-boundary behavior at controlled speed.
