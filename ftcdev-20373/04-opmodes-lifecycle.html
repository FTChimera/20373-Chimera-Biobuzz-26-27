04 / Execution

Use the concrete match entry points that are in TeamCode/src now: tele/TeleOp and autos/Garden8.

The current repo does not route match execution through deleted Ivy-specific base classes. TeleOp is a LinearOpMode; Garden8 is an iterative OpMode that owns scheduling, parking, and shutdown timing.

What this chapter covers

Use this page before changing code in the matching source areas.

  • TeleOp creates DualGamepad, State(RobotMode.TELEOP), and a teleop Robot.
  • TeleOp restores alliance and pose from Blackboard, sets a stick curve, starts teleop drive, then loops on drivers.update() and robot.periodic(robotState).
  • Garden8 resets the Ivy scheduler in init(), builds a plan through PlanBuilder, then executes the scheduler inside loop().
  • Nested alliance subclasses exist in both match entries and set Blackboard alliance before delegating to shared logic.
  • ConfigOpMode is the runtime menu for Blackboard values such as alliance, driver preference, and starting pose.
  • Autonomous-to-teleop pose handoff is written by Robot shutdown, not by a second persistence helper in TeleOp.

TeleOp loop snapshot

This shortened flow matches the current TeleOp.java implementation.

DualGamepad drivers = new DualGamepad(gamepad1, gamepad2);
State robotState = new State(RobotMode.TELEOP);
robot = Constants.createRobot(hardwareMap, RobotMode.TELEOP);
robot.setStartingPose(getStartingPoseAndSetAlliance());
robot.startTeleOpDrive();
waitForStart();
robot.start();
robot.startVision(Vision.Pipeline.APRIL_TAG);
while (opModeIsActive()) {
    drivers.update();
    robot.periodic(robotState);
}

TeleOp details to keep accurate

The main match teleop does a little more than start a drive loop.

  • getStartingPoseAndSetAlliance() first checks Blackboard for alliance and pose, then falls back to the default start pose constants.
  • robot.setDriveStickCurve(x -> Math.signum(x) * x * 1.1) is applied before start.
  • robotState.setGpBindings(drivers.result()) happens once before the active loop, while controller edge state is refreshed by drivers.update() each iteration.
  • The loop publishes telemetry for pose and intake power in addition to running the robot periodic cycle.
  • Red_Tele and Blue_Tele only set Blackboard alliance and then call super.runOpMode().

Garden8 details to keep accurate

The autonomous entry owns its own iterative lifecycle instead of copying the teleop pattern.

  • init() calls Scheduler.reset(), constructs the robot, and schedules startGardenPose(robot).shootPreloads().intakeGarden().
  • start() only calls robot.start().
  • loop() runs Scheduler.execute(), then checks the autonomous time limit and park logic.
  • When the time limit is reached, Garden8 uses robot.stop(false), waits for low velocity or a timeout, then calls saveEndVals() and stops the op mode.
  • stop() still safeguards cleanup by calling robot.stop(true) when shutdown has not already started, then resets the scheduler.

Blackboard and lifecycle ownership

ConfigOpMode uses a selectable menu to write Blackboard.Caption.ALLIANCE, DRIVER, and POSE. Match entries consume those values rather than implementing their own configuration UI.

This split keeps setup decisions outside the match loop, while Robot.saveEndVals() remains the single owner of post-run pose and alliance persistence.

Documentation shortcuts to avoid

A few tempting summaries would be inaccurate for this source tree.

  • Do not describe TeleOp as an iterative OpMode; it subclasses LinearOpMode.
  • Do not describe Garden8 as a deleted planner wrapper; it is the current autonomous entry class.
  • Do not imply a runtime profile picker for currentBot; the runtime menu only affects Blackboard state.
  • Do not move Robot lifecycle responsibility out of these entries when writing guide text.
