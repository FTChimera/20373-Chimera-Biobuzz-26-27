06 / Autonomous

Garden8 is the current autonomous owner for planner scheduling, timeout parking, and pose handoff.

The autonomous flow in source is centered on Garden8, the Ivy Scheduler, and the reusable planner chain returned by PlanBuilder. This guide chapter documents that route instead of removed autonomous entry classes.

What this chapter covers

Use this page before changing code in the matching source areas.

  • Garden8.init() resets the scheduler, creates the robot, and schedules the Garden preload plus intake chain.
  • Garden8.loop() runs Scheduler.execute() every cycle before timeout and parking checks.
  • robot.shouldPark() and Scheduler.isRunning(plan) both feed the decision to call robot.moveToPark().
  • Robot.moveToPark() follows a Pedro PathChain built from the current pose to Common.park.pose().
  • Ivy command helpers are split across RobotIvyBuilder, planner classes, and Pedro helpers rather than a separate commands package.
  • Alliance-specific autonomous variants are the nested redalliance and bluealliance classes in Garden8.

Current Garden8 plan chain

This is the exact fluent path the current autonomous entry schedules during init.

plan = PlanBuilder.startGardenPose(robot)
        .shootPreloads()
        .intakeGarden()
        .schedule();

Garden8 lifecycle checkpoints

These checkpoints are the high-value parts of the current autonomous entry.

  • The scheduler is always reset both before autonomous work begins and again in stop().
  • Timeout handling begins once robot.getOpModeTimeSeconds() reaches RobotMode.AUTONOMOUS.timeLimit().
  • Velocity settling uses a two-second Timer fallback plus a velocity magnitude threshold of 0.2.
  • Normal stop() still preserves Blackboard handoff by calling robot.stop(true) unless an earlier timeout path already called robot.stop(false).

Where autonomous command composition actually lives

Current source spreads Ivy usage across three layers.

  • library/robot/RobotIvyBuilder wraps aggregate robot actions as commands.
  • library/planners/PathPlanner and PathPlannerList compose planner-level commands and transitions.
  • pedroPathing/Pedro provides lower-level path and command helpers for Pedro pathing.
  • Mechanism-level actions such as intake or drive helpers stay on the owning class instead of a separate commands folder.

Autonomous boundaries that remain unfinished

PlanBuilder still has unimplemented loading-side branches and throws when methods are called from the wrong position. The guide should describe only the Garden start path as implemented match flow.

Common still stores many alliance pose placeholders as new Pose(), so any chapter that mentions park, start, or intake poses must clearly treat them as structure, not as tuned field coordinates.

Safe autonomous doc phrasing

Use wording that matches the code without overstating calibration.

  • Say that Garden8 is the current autonomous entry, planner consumer, and parking owner.
  • Say that Pedro paths are followed through the drive mechanism and follower configuration supplied by the active profile.
  • Say that alliance handoff is persisted through Robot shutdown when autonomous periodic has produced a last state.
  • Do not present placeholder loading routes or placeholder Common poses as measured strategy data.

What stays outside Garden8

Garden8 owns scheduling and timeout flow, but it does not replace the shared Robot lifecycle. Drive following, pose persistence, and mechanism shutdown still route through the aggregate robot and its configured mechanisms.

That split is why autonomous docs should still reference Robot, RobotDrive, and planner helpers instead of treating Garden8 as a monolithic subsystem.
