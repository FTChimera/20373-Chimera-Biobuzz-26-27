07 / Planning

Use planner steps for mechanism-aware sequences.

The planner stack is a repository layer on top of Pedro and Ivy. A PathPlanner step owns its start/end pose relationship, path construction, and command. PlanBuilder makes a sequence readable when it combines travel, waits, dynamic vision collection, and parking.

Call a plan from a LinearOpMode

This is the call pattern used by PlannerIntakeVisionAuto: construct registered mechanisms once, build the sequence before start, then schedule and execute it in the active loop.

Robot robot = Constants.createRobot(hardwareMap, RobotMode.AUTONOMOUS);
RobotDrive drive = robot.requireDrive();
Vision vision = robot.requireVision();
PathPlannerList plan = new PlanBuilder(robot, vision, START_POSE)
    .linearPathTo(STAGING_POSE)
    .waitMs(250)
    .intakeWVision(2, createVisionFailSafePath())
    .linearPathTo(PARK_POSE)
    .build();

waitForStart();
plan.schedule();
while (opModeIsActive()) {
    Scheduler.execute();
    drive.periodic(null, RobotMode.AUTONOMOUS);
}

Understand the PathPlanner contract

public interface PathPlanner {
    Pose getEndPose();
    Command run();
    void setStartPose(Pose pose);
    void buildPaths();
}

PathPlannerList turns individual steps into a sequence. The start pose flows from one planner to the next; a step must accurately report its end pose. PathPlanner.asCommand() owns the buildPaths() then run() pairing, so callers do not duplicate that lifecycle.

Built-in stepslibrary/planners/paths/Utils.java currently supplies StartPose, CustomPath, LinearPath, Wait, and IntakeWVision.

Compose a readable PlanBuilder sequence

plan = new PlanBuilder(robot, vision, START_POSE)
    .linearPathTo(STAGING_POSE)
    .followPath(createApproachPath())
    .waitMs(250)
    .intakeWVision(2, createVisionFailSafePath())
    .linearPathTo(PARK_POSE)
    .build();

This is not a generic fluent API: it is an autonomous sequence over the aggregate mechanism set. The builder seeds its list with Utils.StartPose, so the drive follower receives the declared beginning before path steps run.

Builder methodUse
linearPathTo(pose)Create a repo-provided linear planner step from the previous end pose.
followPath(chain)Insert explicit prebuilt Pedro geometry.
waitMs(ms)Insert intentional timing, not a busy wait.
intakeWVision(count, failSafe)Collect with neural-detector results while retaining a deterministic fallback.

IntakeWVision owns a dynamic path decision

Utils.IntakeWVision gets the profile-created Vision, RobotDrive, and Intake from the aggregate. It switches to NEURAL_DETECTOR, retries for a bounded period, filters and scores detector candidates, chooses a sequence, then creates either a Pedro curve-through path or adaptive-handle Bezier segments based on waypoint geometry.

  • Candidate filtering rejects weak confidence, too-small target area, non-finite distance, and excessive lateral offset.
  • It deduplicates nearby detections and scores a forward-ordered collection route.
  • It starts the intake while it follows the selected outbound path.
  • It retains a resolved end pose and does not pretend a dynamic route is guaranteed.
Pipeline ownershipDo not silently leave the Limelight in AprilTag mode when a planner step expects detector output. IntakeWVision.buildPaths() and its start logic explicitly select the neural detector pipeline.

Dynamic paths require a fail-safe and a return owner

Vision can be unavailable, poorly calibrated, or timeout before a valid route exists. IntakeWVision uses the supplied fail-safe outbound chain when it cannot use vision. After the outbound follower is no longer busy, it creates a return line to the step's configured start pose with piecewise heading interpolation. It stops the intake before following the return.

if (shouldUseFailSafePath) {
    startFailSafePath();
}
// After outbound completion:
startReturnPath(drive.mecanumDrive.follower.getPose());

When adding another dynamic planner, make the failure decision explicit. A plan should either choose a known fallback, finish safely, or return a no-op that its caller understands; it should not leave a follower or mechanism running indefinitely.

Use the integration test as the starting point

tests/PlannerIntakeVisionAuto.java is the current Driver Station-visible integration test. It creates an autonomous aggregate, requires drive and Vision, treats Intake as optional for telemetry, starts Vision in detector mode after start, schedules the plan, calls Scheduler.execute(), and calls drive.periodic(null, RobotMode.AUTONOMOUS) in its active loop.

Before adding a new planner step
  • Validate the step with a deterministic fail-safe route first.
  • Keep start/end pose behavior correct so later steps attach to the intended place.
  • Validate optional mechanism absence instead of dereferencing a missing wrapper.
  • Keep detector calibration and robot safety bounds conservative until tested on field.
